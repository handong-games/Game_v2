# Intent System Question Log

## 목적

이 문서는 우리 프로젝트의 인텐트 시스템을 설계하기 위해 먼저 해결해야 하는 질문들을 한 곳에 모아두고, 각 질문에 대해 단계적으로 답을 확정해 나가기 위한 작업 문서다.

이 문서의 목표는 바로 구현하는 것이 아니라, 다음을 명확히 하는 것이다.

- 인텐트가 무엇을 위한 시스템인지
- 어떤 런타임 객체가 인텐트를 소유하는지
- 에디터에서 어떤 데이터를 authoring 해야 하는지
- 행동 선택, 인텐트 공개, 상태이상에 의한 변경이 어떤 규칙으로 동작해야 하는지

## 현재까지의 잠정 합의

아래 항목은 현재 대화 기준으로 이미 잠정 합의된 내용이다.

- 현재 프로젝트는 Unity 프로젝트다.
- GAS 설계 원칙은 Unreal GAS를 참고하되, 구현은 Unity 프로젝트에 맞춘다.
- `GA_Turn`은 실행 스킬이 아니라 턴 컨트롤러 역할을 맡는다.
- 실제 공격/방어/버프 같은 실행은 별도 Ability가 담당한다.
- 플레이어는 다음에 할 행동을 미리 볼 수 있어야 한다.
- 인텐트는 전투 중 상태 변화, 특히 기절 같은 효과에 의해 바뀔 수 있어야 한다.
- 가능한 한 단순한 v1부터 시작한다.

위 항목들은 아직 문서상 최종 확정은 아니며, 이후 질문 답변 과정에서 수정될 수 있다.

## 질문 진행 규칙

- 한 번에 하나의 질문만 확정한다.
- 각 질문은 `미해결`, `진행 중`, `확정`, `보류` 중 하나의 상태를 가진다.
- 이미 합의된 내용이라도, 더 상위 질문의 답이 바뀌면 다시 열 수 있다.
- 구현 세부보다 먼저 책임, 데이터 소유권, 런타임 흐름을 확정한다.

## 확정된 답변

### Q1. 인텐트의 목적은 정확히 무엇인가?

- 확정 답변:
  - 인텐트의 목적은 플레이어가 전투에서 스킬을 사용할 때 고려할 요소를 추가하는 것이다.
  - 플레이어가 현재처럼 코인 결과만 보고 사용할 수 있는 가장 강한 스킬을 고르는 단순 전략에서 벗어나야 한다.
  - 플레이어는 상대의 다음 행동을 보고, 그 위험을 해석하고, 그에 대응하도록 스킬을 선택할 수 있어야 한다.
  - 인텐트는 단순한 행동 예고보다 `위험 예고`를 우선하는 개념으로 정의한다.
  - 즉 인텐트는 "적이 무엇을 할 것인가"보다 "그 행동이 플레이어에게 어떤 위험을 만들 것인가"를 전달해야 한다.

### Q2. 현재 공개 중인 인텐트의 authoritative owner는 누구인가?

- 확정 답변:
  - 현재 공개 중인 인텐트의 authoritative owner는 `CombatCard.IntentComponent`다.
  - `GA_Turn`은 다음 행동과 인텐트를 계산하고 `IntentComponent`를 갱신하는 역할을 맡는다.
  - UI는 `IntentComponent`를 읽기만 해야 하며, 인텐트를 직접 계산하거나 재구성하지 않는다.

### Q3. 인텐트는 어떤 단위에 붙는가?

- 확정 답변:
  - 인텐트는 개별 Ability asset에 직접 붙는 것으로 보지 않는다.
  - 인텐트는 이번 턴에 확정된 현재 행동 상태, 즉 `Prepared Action`에 붙는 것으로 본다.
  - Ability는 행동의 source가 될 수 있지만, 현재 공개 중인 위험 정보의 직접 소유자는 아니다.
